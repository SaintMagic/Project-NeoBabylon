## Proposed inventory and classification contract

1. Stream a complete manifest for each of the exact 56 roots without following reparse points. Record normalized relative path, entry type, file length, timestamps/attributes needed for stability checks, volume serial and file ID where available, hard-link count, and reparse tag plus exact raw reparse payload. Bound total elapsed time and per-file operations; report progress and counts without retaining the whole tree in memory. Any enumeration, identity, or payload read failure makes the inventory incomplete and blocks readiness.
2. Group regular-file names by volume serial plus file ID. For each identity compare `m`, the number of names found in the in-scope roots, to the filesystem-reported link count `n`: `m == n` means all links are accounted for in scope; `m < n` requires selective enumeration of external aliases and an explicit disposition; `m > n` is inconsistent evidence and fails closed. Do not follow reparse points during alias discovery. Do not claim external alias reconstruction unless it is independently evidenced.
3. Preserve reparse entries as reparse entries, using the captured tag and exact raw payload; never substitute a resolved target or normalized path. Fixture-qualify each encountered supported tag/type and verify raw readback. Unknown, unreadable, malformed, or unsupported reparse entries block the gate. Preserve the two historical QA junction payloads byte-for-byte, including their historical target strings. One target is already malformed/dangling. The other points inside OLD Data and will become dangling after the move if its raw target is preserved. Record these distinct existing and post-move semantics; do not follow, normalize, or repair either target.
4. Assign every manifest entry exactly one disposition: protected/preserved, explicitly excluded reproducible cache, or blocking unknown/non-reconstructible/unsupported. Do not infer exclusions from names such as `cache`, `target`, `build`, or `tmp`; exclusions require an explicit, reviewable, reproducibility-backed path rule and digest-bound manifest. Keep historical QA and evidence, the locked App Server binary, Git administration/pointers, and every SQLite database with its extant WAL, SHM, or rollback-journal members in protected sets. No unknown entry is silently skipped.
5. Measure the complete streaming inventory on a scale fixture representing the observed file, directory, hard-link, reparse, SQLite, and nested-worktree scale. State a wall-clock and memory ceiling, test interruption/error behavior, and show deterministic complete counts and digest on repeat runs. If a complete live Data pass cannot meet the limit, remain blocked and revise the inventory method; do not fall back to a partial manifest.

## Proposed backup and cutover gates

- Once path-owning writers and relaunchers have been operationally quiesced, take an independent, access-restricted backup of the protected subset. Evidence should identify the controlled writers/relaunchers and record repeated process/tree checks; the scanner itself cannot prove continuous quiescence. This is selective recovery coverage, not a full-volume image. Capture each SQLite database and its extant sidecars as one consistent set. Read back the backup and compare its manifest, content digests, reparse payloads, and protected metadata. Record omissions explicitly. The backup must not expose credential values.
- After backup completion and readback, create a fresh complete Preflight. Bind its digest, the backup manifest/readback digest, exact 56-pair manifest digest, and active-lock/locked-binary identity into the Move authorization record. Maintain the operational quiescence condition through controlled writers/relaunchers and repeated checks, alongside manifest stability checks up to each rename. Any observed writer/relauncher, digest drift, missing entry, or expired inventory invalidates authorization and stops before the next rename; these checks are evidence, not scanner proof of quiescence.
- Keep the approved same-volume whole-root rename and durable per-pair intent/completion journal. No copy-delete, merge, overwrite, or live mutation during qualification. Before Git repair, compare the moved inventory and protected bytes to the fresh baseline, including the complete locked binary. Then repair the four exact linked worktrees and verify all five worktrees' common-dir, HEAD, index/staged, unstaged, untracked, ignored manifests and relevant bytes; permit only identified Git linkage-file changes.
- Activate the candidate runtime lock only after all 56 roots, pre-repair comparisons, and Git links verify. Then perform the existing explicit-root host launch and restart checks, confirming the actual launched executable path and full hash. A separate QA build does not substitute for locked-binary identity.

## Recovery guarantee

For a failed rename sequence, recovery first uses the journal to inverse only verified completed same-volume renames, in reverse order, into empty original paths. If original objects are damaged, use the independently read-back protected-subset backup selectively. Keep the host and tests stopped until original paths, old lock, and required Git links are verified. This is not a guarantee to reconstruct explicitly excluded reproducible bytes, aliases outside the captured scope, or data after volume loss. If inverse rename or selective restore cannot be verified, stop for manual recovery; never delete an occupied path or silently rebuild data.

## Proposed implementation slices (not started)

These are future, serially gated slices with disjoint file ownership. A1 has been dispatched but has not passed; its implementation and evidence remain pending. Each slice requires failing RED fixtures before implementation, passing GREEN fixtures after, and an independent review of the complete owned diff and evidence before the next slice. They do not expand product features.

1. **A1 — C# physical-entry streaming inventory:** own only the dispatched `tools/WorkspaceConsolidationInventory/` project (`.csproj`, `Program.cs`) and its identified PowerShell tests. Implement streamed physical-entry enumeration without following links/reparse points, recording the required per-entry metadata and exact reparse data, with bounded resource use and machine-readable incomplete/error outcomes. A1 does not implement identity grouping/classification or claim to have passed. No edits to the existing mover, backup files, runtime lock, or other tests.
2. **A2 — disk-backed identity grouping and classification:** own a separately named component and its tests, with paths to be assigned without overlap before implementation. Consume A1's manifest; group by volume plus file ID, compare in-scope names to reported link count, apply the `m == n` / `m < n` / `m > n` dispositions, and classify every entry under explicit protected/excluded/blocking rules. Fail closed on incomplete identities or unknown types.
3. **Protected-subset backup and readback:** own only `scripts/WorkspaceConsolidationBackup.ps1` and `tests/qualification/WorkspaceConsolidationBackup.Tests.ps1`. Consume the reviewed A1/A2 contract; implement restricted, independent backup/readback for protected categories, including consistent SQLite sets and qualified link/reparse semantics. Fail closed on incomplete or unsupported content.
4. **Digest-bound mover gate:** own only `scripts/WorkspaceConsolidation.ps1` and `tests/qualification/WorkspaceConsolidation.Tests.ps1`. Require fresh post-backup Preflight, bound evidence digests, operational quiescence evidenced through controlled writers/relaunchers and repeated checks, same-volume journal transitions, pre-Git-repair comparisons, four-link repair, and verified inverse behavior. Preserve the exact approved 56-root manifest; no live Move during this slice.
5. **Serialized live qualification and cutover:** only after independent reviews of A1, A2, backup, and mover slices pass, execute the already-approved exact-root sequence and record evidence under a unique restricted `.local/QA` run. This operational slice owns only that run's evidence and the authorized runtime-lock activation; stop on any failed gate. Verify the actual host launch/restart. No commits, pushes, broad toolbox, packaging, or production feature work.

Scale qualification may combine synthetic stress input at or above the observed manifest row count with smaller filesystem fixtures that exercise real file IDs, hard links, reparse entries, SQLite sidecars, and nested worktrees. It need not physically create 616,070 files. State and enforce wall-clock and memory ceilings; test interruption/error behavior and deterministic complete counts/digests. A partial live inventory remains a blocker regardless of synthetic fixture results.
